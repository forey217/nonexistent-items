# 长时间运行排查与性能优化 v39.2

## 结论与范围

用户反馈停留较久后卡顿。首次检查时旧游戏已关闭，无法取得发生卡顿那一刻的进程数据；没有把问题归因于试玩身份、未保存或已证实的内存泄漏。

以已交付的 v39.1 程序为基线，使用同版本 Godot 的实际 ANGLE 渲染运行，而非只跑无图形测试。基线覆盖主界面、大厅、第一关静置、12次世界切换和6次大厅/关卡往返，约148秒。节点、资源和引擎内存没有随往返累积；退出场景后节点回到根节点。

确认的开销是高刷新率窗口下没有帧率预算、第一关大量静态零件独立提交绘制，以及已隐藏的旧2D地图/机关贴图仍加载并更新。实际性能还受系统其他负载影响，没有测得卡顿时的温度或系统内存提交量，因此没有断言所有卡顿原因已排除。

## 修改

- 主窗口前台最高60帧、失焦后台最高30帧。物理更新仍为原来的60Hz，未改变机关时序或移动速度；无图形检查不受限帧影响。
- 相同材质、阴影模式和渲染层的静态不透明零件合为网格。保留墙的独立分区、可移动镇纸根节点、透明玻璃、灯光材质和所有真实碰撞。
- 关内旧2D地图、旧机关贴图和隐藏家具表现不再加载/更新。保留其交互位置与碰撞，实际显示仍由已有3D正交场景负责。
- 没有修改存档格式和玩家已有记录。

## 实测对照

同一场景、默认视角、冰晶世界且霜冻动画结束后：

| 指标 | v39.1基线 | 优化后 |
| --- | ---: | ---: |
| 每帧绘制调用 | 1381 | 665 |
| 场景节点 | 3046 | 992 |
| 引擎静态内存统计 | 约438.5MB | 约349.1MB |
| 贴图显存统计 | 约207.3MB | 约132.3MB |

绘制调用约减少52%，贴图显存约减少75MB。它们不是任务管理器中的“进程总内存”；驱动、系统和资源缓存也会占用进程内存。优化版该进程的实测工作集约697MB，最后连续静置阶段基本保持不变。

优化版实机运行约308秒，包含20秒主界面、20秒大厅、40秒初始关卡静置、12次切世界、6次场景往返及最后180秒静置。最后静置时引擎统计约349.09MB、节点992个、资源105个，没有继续增长。此测试没有复现持续泄漏，不代表无限时长和所有路径都已覆盖。

## 验证与交付

- 静态合批、透明边界、几何位置、头部碰撞、隐藏贴图、六次场景释放及退出释放：23项通过。
- 原有解谜66项、世界胶片切换34项、存档41项、剧情85项通过。
- 最终Windows导出程序另跑41项存档/完整通关检查通过，无脚本错误。
- 实机截图保留现有画风；没有重新制作地图或降低主场景分辨率。

本次工作区同时在进行第二关和其他界面改动。性能试玩包从单独冻结的已交付v39源码加本次性能修正导出，以免将尚在施工的功能混入；相同修正也已写入当前工程。程序位于 `builds/performance-v39.2/世界不按说明书-优化试玩-v39.2.exe`。

原始实机采样、系统进程内存采样、截图与报告位于 `.artifact_work/memory-investigation-v40/`，交付包中附有效报告。最初基线的Windows采样误采到了控制台启动器，未用来做进程总内存比较；上表使用Godot内部渲染/资源指标，优化版Windows采样直接读取实际游戏进程。

官方指标和API依据：[Performance](https://docs.godotengine.org/en/stable/classes/class_performance.html)、[帧率上限](https://docs.godotengine.org/en/stable/classes/class_engine.html#class-engine-property-max-fps)、[SurfaceTool](https://docs.godotengine.org/en/stable/classes/class_surfacetool.html)。
