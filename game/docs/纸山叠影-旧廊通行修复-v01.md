# 《纸山叠影》旧廊通行修复 v01

## 定位与根因

反馈图对应上层工具区入口的小段显影旧廊，原位置约为平面坐标 `(5,10.5)`，不是右侧 `(18,11)` 的可留影木桥，也不是下层的固定跨渠通路。

本轮修改前，Windows 图形程序复现了两个问题：

1. `paper_mill_room.gd::is_walkable` 和 `paper_mill_view.gd::_sync` 都把 `clip_owned` 当作旧廊永久开放条件。取得夹子后，即使未固定任何对象，旧廊也保持显示和可走。
2. 缺口仅覆盖一小段渠面，没有接上工具区两侧的实际边界。未取得夹子、旧廊尚未显影时，AStar 仍能从右端绕到工具区入口。原始路径与复现截图保存在 `showcase/checks/corridor-fix-v01/before`。

## 实际修改

- `paper_mill_state.gd` 新增 `old_corridor_solid()`，只读取所属上层 `worlds[0]==3`。旧廊没有夹环，不支持留影固定；持有夹子、固定接物台或右侧木桥均不会解锁旧廊。
- 同处统一定义旧廊缺口与桥面范围。仅将该处缺口补接到现有工具区边界，桥面相应接到两岸；普通石板区域、下层固定桥和右侧可留影木桥沿用各自规则。
- `old_corridor_blocks()` 按人物脚底半径留出岸边与桥面宽度余量。手动移动、分段位移检查、AStar 点与路径平滑共同使用 `is_walkable()`，不能斜切水面或靠大步长穿过缺口。
- `paper_mill_view.gd` 的旧廊显示、切口和桥面均引用同一状态和范围，不再读取 `clip_owned`。没有新增桥梁或夹子能力。
- 导航签名包含旧廊支撑状态和人物所在层；路径请求前检查签名，拓扑改变时验证剩余路径，失效即取消路径和待执行互动。合法路径不会因无关变动一律被清空。
- 人物脚底仍占用旧廊时，拒绝会撤掉支撑的上层规则切换，并提示先回桥头。这沿用项目既有木桥的支撑保护思路，人物不移动、不掉层；另一层仍可独立切换。
- 旧存档若正站在非显影的无支撑位置，会清空路径，在同层按保存位置的前后半段恢复到最近的稳定岸边，避免恢复到水面或跨到另一岸。合法显影存档保留原位置。

## 范围与兼容

保留当前工作区的薄玻璃 UI、逐句配音、双层规则、镇纸运输、吊台、楼梯、护栏、相机与场景细节。旧廊修复不改变任务顺序、夹子取得条件、两处锚点、存档格式或归档入口。

## 验证与录制

新增入口 `--paper-corridor-check --artifacts=<绝对路径>`，可使用 `--record-corridor` 同步保存真实渲染帧。覆盖三种非显影规则、持有夹子与两种固定目标、双向手动/点击、斜向与大步长、两层独立、旧路径失效、支撑保护、存档修复，以及三个倍率和旋转边界。录像来自 Windows 原生图形程序，自动输入驱动实际人物移动；不是效果图动画。固定60Hz推进、每4帧采集一次，以15fps编码，不作为性能帧率基准。

交付目录中的检查报告列出最终导出 exe 的实际检查项数、原始报告和录像。保留旧 Windows 版本。
