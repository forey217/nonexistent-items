## 历史人物移动模块 v0.3

Godot 4.7.2 标准版，GDScript，Compatibility渲染。当前为单层斜俯视人物移动与碰撞测试场景。

## 运行

直接双击工作区`builds/movement-v03/不存在的物品-移动测试-v03.exe`。

v0.3重新校准了正面/背面的肩部挂接、袖子的旋转中心与前后遮挡；站立落点不再交叉，腿部使用小幅屈膝。移速为145像素/秒，完整左右脚周期为180像素，对应约1.61步/秒；v0.2为185像素/秒与110像素周期，约3.36步/秒。摆臂幅度从0.43弧度降为0.12弧度，抬脚从7像素降为3.2像素。本次只调整已有分件素材的运行时绑定和动画，没有生成新图片。详细自检记录见`docs/步态-v03-自检记录.md`。

编辑源码时，在Godot中导入本目录`project.godot`，运行主场景`main.tscn`。

## 操作

- WASD或方向键：走动，斜向速度已归一化。
- 鼠标左键点击空地：自动绕开家具，到达目标点。
- WASD可立即接管点击移动，松开后不恢复旧路线。
- Esc：取消点击路线。
- R或重置按钮：返回起点。
- F2或碰撞显示按钮：显示脚底碰撞圆、家具占地和当前路线。
- F3：放大查看四个朝向的连续步态，行走4秒、停步1秒循环；Esc返回测试房间。
- 右键：保留道具入口，当前只显示提示。

## 模块组成

- `scenes/yanyue.tscn`与`scripts/yanyue_mover.gd`：可复用人物组件。脚底圆形碰撞、手动移动、路线跟随、取消与焦点丢失处理。
- `scripts/yanyue_walk_rig.gd`：四朝向的连续纸片骨骼步态。两腿交替接触/摆动、屈膝、反向摆臂、身体起伏与0.1秒起停收势；按实际移动距离推进，受阻停止原地迈步。
- `scripts/walk_demo.gd`：F3步态展示，与游戏共用同一个动画组件。
- `scripts/bureau_navigation.gd`：按人物宽度扩张障碍的AStar网格，禁止斜向切角，并用圆形扫掠检查路线平滑。
- `scripts/bureau_prop.gd`：透明家具、独立实体占地和脚底排序位置。
- `scripts/movement_room.gd`：输入、测试房间、碰撞环境、寻路与模式反馈。

将人物组件加入其他关卡时：设置环境碰撞到第1层；人物位于第2层并检测第1层；让人物和家具作为同一启用Y排序节点的直接子节点；用家具的落地位置作为排序基点。房间导航须按新关卡的实际碰撞区域重新生成。

## 当前范围

包含人物四个主要朝向、连续步态、键盘/点击移动、静态墙体与家具碰撞、家具前后遮挡，以及可观察的碰撞显示。步态是运行时关节插值；没有将重复的相似站姿计作新增手绘帧。

高低层通行、跳跃、正式道具、NPC剧情、漫画过场和正式关卡尚未接入。测试房间中的观测球仅为美术陈设，不锁定剧情修复道具。

## 检查

开发时可用Godot命令行运行：

```text
Godot --headless --path <本项目目录> --fixed-fps 60 -- --self-test --artifacts=<报告目录>
```

测试检查实际物理移动与接触，包括墙体、家具、多次路线请求、手动接管、取消、角落、4000像素每秒的碰撞压力测试和重置。不会用测试通过代替后续每个关卡的单独验证。

`tools/inspect_rig.py`只读取生成图透明度的连通区域，输出部件元数据，不修改图片；Godot以图集区域和纹理网格使用素材。家具元数据仍由`tools/inspect_atlases.py`生成。

本机原生OpenGL启动曾在`nvoglv64.dll`中崩溃，v0.2将Windows Compatibility驱动设为`opengl3_angle`，已在RTX 5060 Laptop上完成本地渲染与导出包启动检查。该驱动为Godot官方支持的Windows选项：[ProjectSettings官方说明](https://docs.godotengine.org/en/4.6/classes/class_projectsettings.html#class-projectsettings-property-rendering-gl-compatibility-driver-windows)。未更改系统驱动。
